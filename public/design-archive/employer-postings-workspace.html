Anatomy

Five stacked sections that ran linearly down a single scroll.

1 · DSPageHeader hero

Studio variant — linear-gradient(135deg, #1e1b4b 0%, #312e81 35%, #6b21a8 70%, #831843 100%) base with four radial-gradient drift blobs (violet top-left, pink top-right, indigo bottom-left, red bottom-right). White-disc icon at shadow-cover-disc. Curve-down SVG at the bottom hides the seam to the page body.

2 · Stats strip

Four StatChip cells: Postings (raw + active count), Applicants (raw + new badge in amber when >0), In progress (reviewing → offer), Hired (lifetime). Even grid; collapses to 2-col on mobile.

3 · Action queue

Amber-tinted panel surfacing items needing attention: New applications, Stale rows (in a stage >7 days), Offer awaiting response (>2 days). Each row jumps the user directly to the applicant, expanded inline.

4 · Posting rows

One row per posting. Collapsed: status chip + title + location + applicant count + new badge. Expanded (click ▾): full applicant pipeline inline (kanban-style stage lanes with drag-drop). Lazy-loaded on first expand.

5 · Inline forms

Schedule interview / send offer / create new posting all open as inline drawers — no route change. The HrWorkspace client component owns every mutation.

+ slotAboveContent

A prop on HrWorkspace that renders any content between the hero strip and the workspace body. Used by the page shell for the admin DemoSeederBar + the SetPasswordBanner notice, so they sit BELOW the hero instead of slipping above it.

Originally lived in src/app/(dashboard)/employer/postings/page.tsx + src/components/employer/workspace/HrWorkspace.tsx. That route now 308-redirects to /employer, which carries the brand-stage hero with the wavy aurora cover banner. The per-posting deep routes (/employer/postings/[id]/...) still exist for applicant management; only the workspace's linear index/dashboard treatment is retired.
